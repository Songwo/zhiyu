# 通用资源关联约定

关联支持服务器、域名、邮箱、AI 订阅、账号与密钥、证书、服务、自定义资产、U 卡、eSIM、手机号、自建节点与文档。卡片和自定义资产沿用服务资产标识；节点使用所属服务器与节点自身的稳定组合标识。

任意两个不同的、实际存在的资源都可以建立无向关联，包括同类型的不同记录和两篇文档。自连、未知类型、已删除目标和重复关联不创建新边。关联表示用户保存的联系，不自动推断登录依赖或授权。

## 数据与兼容

- `Snapshot.links` 的端点扩展为通用资源引用：`{kind,id}`。关联去重和删除按类型加 ID 识别，不能只比较 ID。
- 继续读取旧号码的 `subscriptionIds` 和文档的 `bindings`，汇入同一个关系视图；两端查询和解除结果一致，旧资料无需重新录入。
- 号码与 AI 订阅的写入同时维护旧字段，号码编辑不清除其他种类的关联。
- 文档与普通资产保留原文档绑定写入流程，保存前处理待提交草稿，正文不能被关联操作覆盖。新增的文档间、号码、节点关联存入通用连线，不写入正文。
- 文档引用在资产资料载入时可能尚未读取，不能因文档列表未加载就丢弃连线；真正删除资源时清理相关连线，关系视图不显示不存在的端点。
- 完整工作区备份、恢复和同步保留所有类型的关联。使用新关联能力的设备需使用支持该能力的版本。

## 验收范围

文档与普通资产的绑定通过已有文档地址的 `PATCH /api/web/documents/:id` 更新，只接受 `{binding:{kind,id},remove:boolean}`。该接口要求现有登录与请求来源校验，检查资源存在，服务端在文档保存队列内只修改绑定元信息。桌面 `documents:bind` 使用相同实现。正文自动保存使用 `preserveBindings:true` 保留最新的绑定，并拒绝复活已删除文档；该字段不写入文档文件。

规则和真实 HTTP 测试覆盖 23 个合成资源的 253 种两两组合，检查添加、反向去重、序列化和解除；另行检查删除清理、旧号码兼容、同步合并和加密备份恢复。真实界面验收使用代表场景，包括号码一次关联其余 22 个资源、刷新保留、反向解除、文档绑定及文档间关联。矩阵测试不等同于对每种组合逐一进行手工界面验收。

Web 与桌面使用相同规则，保存完成须等待实际存储应答。失败后保留草稿并显示错误，不能提前显示成功。旧文档桥接缺少安全绑定接口时明确要求升级，不用整份正文回写冒充绑定成功。AI 来源中的号码和节点也使用统一跳转；节点单独计数，不重复计入核心资产的费用或异常统计。

隐私检查确保关系图和自动建议不读取密码、节点配置、完整手机号、卡号或文档正文。既有本地动效修改与本次关联修复独立验收，发布时另行统一安排。

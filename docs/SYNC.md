# 桌面端与网页版同步（ZSP）

把桌面版的资产、文档和（可选的）密钥库同步到自己 VPS 上的网页版，两边都能改，合并后一致。同步协议叫 ZSP（Zhiyu Sync Protocol）v1，设计目标按优先级排序：

1. **服务器拿不到密钥库里的任何东西**。密钥库同步的只是 AES-256-GCM 密文，主密码和密钥从不离开设备。
2. **配对一次，之后不依赖 TLS 也不怕中间人**。配对用一次性短码做 PAKE，之后每次会话用双方固定公钥互相认证。
3. **绝不静默丢数据**。冲突保留两份，删除与修改冲突时保留修改。
4. **能撤销**。任意一端都可以随时解除配对，服务器侧撤销立即生效。

## 威胁模型

| 对手                                             | 能做什么                             | ZSP 的应对                                                                                                                              |
| ------------------------------------------------ | ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- |
| 网络中间人（含纯 http 的局域网、公共 Wi-Fi）     | 读、改、重放、丢弃流量               | 会话在 http 上也由 AEAD 加密与认证；服务器与设备互相用 Ed25519 认证；临时 X25519 密钥带来前向保密；计数器与随机数防重放                 |
| 抢先配对或猜配对码的人                           | 对服务器发起配对                     | 配对码 50 位熵，5 分钟有效、只能用一次、错 3 次作废、每个来源限流；PAKE 使抓包后无法离线穷举                                            |
| 冒充服务器的人                                   | 让桌面端连上假服务器                 | 配对码只有真服务器与桌面端知道，PAKE 不通过就不会配对；配对后固定服务器公钥，换服务器会被拒绝                                           |
| 被入侵的 VPS（网页版本来就保存明文的资产和文档） | 读资产与文档；篡改或回滚数据；偷会话 | 密钥库只有密文，无法解密也无法伪造单条记录（GCM 认证）；服务器序号回退或分叉时桌面端拒绝同步；系统加密保存的 Token / API Key 不参与同步 |
| 被偷的桌面设备                                   | 持有设备私钥                         | 设备私钥由系统安全存储加密；网页版「已配对设备」里一键撤销，服务器立即拒绝并断开会话                                                    |
| 被偷的备份或数据目录                             | 离线读取                             | 密钥库离线穷举受主密码强度与 scrypt（N=2¹⁷）限制；设备私钥由系统安全存储或服务器密钥加密保存                                            |

**不在范围内**：已经控制了你桌面或服务器 root 的攻击者（他们能直接读内存与文件）；你自己泄露了主密码；服务器在你解锁密钥库的浏览器里注入恶意脚本（网页版固有风险，建议只经 HTTPS 访问自己的域名）。

## 记号

`lp(a, b, …)` 表示把每一项加 4 字节大端长度前缀后拼接，保证不同字段不会拼出歧义。哈希为 SHA-256，MAC 为 HMAC-SHA-256，KDF 为 HKDF-SHA-256，AEAD 为 AES-256-GCM（96 位随机数位置由计数器填充），签名为 Ed25519，临时密钥交换为 X25519，PAKE 群为 ristretto255。所有标签都带 `ZSP1` 前缀做域分离。

## 一、配对（一次）

在**已登录的网页版**「设置 → 同步」点「生成配对码」，得到形如 `K7M2Q-9XWPD` 的码（Crockford Base32，10 个字符，50 位熵），有效 5 分钟。在桌面端输入服务器地址与配对码。

PAKE 采用 CPace 风格的平衡式协议（ristretto255）：

1. 桌面请求开始，服务器返回随机 `sid`（16 字节）。
2. 双方各自计算生成元 `g = HashToRistretto(lp(code, sid, "ZSP1 pairing"))`。桌面取随机标量 `ya`，发送 `Ya = g^ya`；服务器取 `yb`，返回 `Yb = g^yb`。双方都拒绝单位元和无法解码的点。
3. 共同点 `K = g^(ya·yb)`（同样拒绝单位元）。`ISK = HKDF(K, salt = lp(sid, Ya, Yb), info = "ZSP1 pair isk")`，再派生出 `kS`、`kC`（确认密钥）和 `kEnc`（加密密钥）。
4. **桌面先证明**：桌面发 `tagC = HMAC(kC, lp("C", sid, Ya, Yb))`，服务器验证；验证失败记一次失败，累计 3 次作废这个配对码。服务器**只有在 `tagC` 通过后**才回 `tagS = HMAC(kS, lp("S", sid, Ya, Yb))`，桌面再验证它。这个顺序很重要：如果服务器先发确认标签，攻击者每发起一次会话就能在本地验证一个猜测，而服务器看不到失败，计数就形同虚设。
5. 在 `kEnc` 加密的通道里互换身份：桌面发 `devicePub` 与对 `lp("ZSP1-PAIR-DEV", sid, Ya, Yb, devicePub)` 的签名（证明持有私钥）；服务器在 `tagC` 通过后返回 `serverPub` 与对 `lp("ZSP1-PAIR-SRV", sid, Ya, Yb, serverPub, devicePub)` 的签名。桌面验证 `tagS` 和这个签名后**固定** `serverPub`，服务器登记设备。码随即作废。

安全性来自：抓到全部配对流量的人必须对每个猜测发起一次在线尝试才能验证，而验证失败 3 次就作废、每个配对码最多接受 8 次密钥交换，猜中概率不超过 8/2⁵⁰。服务器与桌面双方的公钥都绑定进了经过 PAKE 认证的转录，中间人无法替换。

页面与桌面端都会显示服务器公钥的 SHA-256 指纹，方便你肉眼核对（可选，不是安全前提）。

## 二、会话（每次同步）

配对后，每次同步先做一次 SIGMA 式的相互认证并建立会话密钥：

1. 桌面发 `{deviceId, epkC, nC}`（X25519 临时公钥与 32 字节随机数）。
2. 服务器查设备（未登记或已撤销一律同样的错误），生成 `epkS`、`nS`，计算转录哈希 `th = SHA-256(lp("ZSP1-SESSION", deviceId, epkC, nC, epkS, nS, serverPub, devicePub))` 和共享秘密 `X25519(eskS, epkC)`（拒绝全零结果），派生两个方向的密钥 `kc2s`、`ks2c = HKDF(shared, salt = th, info = "ZSP1 session keys")`，并返回 `{sid, epkS, nS, sigS = Sign(serverKey, lp("ZSP1-SRV-SIG", th))}`。
3. 桌面用固定的 `serverPub` 验证 `sigS`，派生同样的密钥，再用 `kc2s` 加密发送 `sigC = Sign(deviceKey, lp("ZSP1-DEV-SIG", th, sigS))`。服务器验证后会话生效。
4. 之后每条消息由 `AEAD(k, counter, aad = lp(th, direction, counter))` 加密。计数器每个方向严格递增，服务器只接受下一个期望值，乱序、重复、回放都被拒绝；会话 15 分钟或空闲 5 分钟后过期。

前向保密：会话密钥只来自临时密钥，长期私钥以后泄露也解不开历史流量。

## 三、数据与合并

同步范围只含备份范围内的文件（`assets.json`、`documents/*.json`、`vault.enc`），且排除由本机系统安全存储加密的凭据文件（Cloudflare Token、模型 API Key、图床 Key、用量来源凭据），这些在网页版重新填写。设置里可以分别开关「资产与关联」「文档」「密钥库」；**密钥库默认关闭**。

服务器只做存取和比较交换（CAS），不做合并。桌面端持有「上次同步后的基线」，用三方合并（基线、桌面、网页）：

- **资产（assets.json）**：按 `id` 做记录级三方合并，字段级取变化的一方；两边改了同一字段取较新的一方，被覆盖的值写入同步日志；一边删除、一边修改时**保留修改**；没有 `id` 的列表（关联）按集合合并。
- **文档**：整篇三方合并；两边都改时较新的作为正文，另一份另存为「（冲突副本）」，不丢内容。
- **密钥库**：在密文层按记录合并（每条记录是独立的 GCM 密文，不需要主密码也不需要解密）；同一条记录两边都改时保留较新的，被覆盖的密文保存为本机文件 `vault.conflict-<时间>.enc` 以便找回。头部（盐、KDF 参数、校验块）不同表示两边的主密码不同：只有一边改过则整体采用改过的一边，两边都改则**不自动处理**，等你选择以哪一边为准。

每个文件上传前，服务器按文件类型校验结构、大小与路径白名单，上传后校验 SHA-256 才落盘。

**回滚与分叉检测**：服务器为每次观察到的资料状态递增序号，并用服务器密钥签名「序号 + 清单哈希」。桌面端记住见过的最大序号：序号倒退或同序号不同内容时拒绝同步并提示（例如服务器被还原了旧备份）。确认是你自己还原的，可以在界面里选择「接受服务器当前状态」。

## 设备管理

服务器保存已配对设备（设备 ID、名称、公钥、创建与最近同步时间），并保留最近的同步与安全事件。网页版「同步」页可以撤销设备；桌面端也可以主动解除配对。撤销后新会话被拒绝，已有会话立即断开。服务器私钥由服务器密钥加密保存，桌面设备私钥由系统安全存储加密（系统只提供明文存储时拒绝保存）。

## 参数

| 项                 | 值                                                           |
| ------------------ | ------------------------------------------------------------ |
| 配对码             | 10 位 Crockford Base32，50 位熵，5 分钟，一次性，错 3 次作废 |
| 同时进行的配对会话 | 最多 4 个，每个 60 秒；每个配对码最多 8 次密钥交换           |
| 会话               | 15 分钟总时长、5 分钟空闲、最多 50000 条消息                 |
| 单个文件           | 64 MiB，分块传输 1 MiB                                       |
| 错误限流           | 同一来源 15 分钟内失败 10 次后暂停                           |

## 已知限制

- 服务器被入侵后，攻击者可以读取并修改**不在密钥库里**的资产和文档，这与网页版本身的保存方式一致；ZSP 保证的是他无法读取密钥库明文、无法让桌面端接受回滚后的状态。
- 网页版在浏览器里解锁密钥库，意味着你要信任你的服务器提供的页面脚本。对安全要求最高的凭据，可以不开启密钥库同步，只在桌面使用。
- 同步依赖两端时钟大致准确，仅用于「谁更新」的平局判定，不影响安全性。
- 这是自研的协议组合（构件均为标准算法与通用库），没有经过第三方审计。设计与测试向量见仓库，欢迎审阅。

# 云服务与探针使用指南

「云服务与探针」把 Cloudflare 资源和知屿独立监控接入本机资产，方便查看状态、管理 DNS，并将主机或服务与文档、账号建立关系。

本文对应本次未发布的开发分支。以下入口存在于当前源码；现有安装包（包括本机已安装的 1.7.2）不会因为文档更新而自动获得这些功能。

## 从哪里进入

桌面版打开「设置 → 云服务与探针」，或在「服务资产」顶部点击「云服务与探针 → 管理连接」。点击「添加连接」，选择 Cloudflare 或知屿独立探针。同一工作区可以保存多个连接，通过连接名称切换。

连接 Token 由操作系统加密保存在本机，不写入资产或浏览器存储。编辑连接时，Token 留空会保留原值。操作系统加密存储不可用时会拒绝保存、读取凭据；不会退回明文保存。

## 接入 Cloudflare

1. 在 Cloudflare 创建自定义 API Token，限定需要访问的账户和域名。按需添加账户设置、Zone、DNS、Workers Scripts、Cloudflare Pages、Cloudflare Tunnel 的读取权限；修改 DNS 另需对应域名的 DNS 编辑权限。完整范围见 [Cloudflare 接入](CLOUDFLARE.md#token-权限)。
2. 添加 Cloudflare 连接，填写连接名称和 API Token，点击「保存连接」。使用 API Token，不使用 Global API Key。
3. 连接后可搜索资源，按域名、Workers、Pages、Tunnel 筛选。部分资源权限不足会单独提示，其他可读取资源仍显示。

资源清单表示服务商返回的资源与状态。Workers、Pages 的状态显示未知，不等于服务故障：清单本身不能证明网站可用，需要另建 HTTP 检查。Workers 清单没有完整访问地址时，知屿不会拼接一个猜测地址。

当前 Cloudflare 管理范围是读取这些资源、关联资产，以及 DNS 操作；不包含发布 Workers、部署 Pages 或修改 Tunnel 配置。

### 导入或绑定资产

在资源卡片点击「导入或绑定资产」，选择「导入为新资产」或已有资产：

| 远端资源 | 对应本机资产 |
| --- | --- |
| Cloudflare 域名 | 域名 |
| Workers、Pages、Tunnel | 服务 |
| 探针主机 | 服务器 |
| HTTP/TCP 检查 | 服务 |

同一连接中的同一个资源重复导入会复用已有资产，保留本机名称、备注、标签和关系。绑定已有资产也只增加来源引用，不覆盖本机资料。一个资产已有其他来源时，需要先解除原绑定。

打开已绑定资产的详情，可查看远端状态、探针指标，或进入域名的 DNS 管理。再使用现有资产关系功能，将它与文档、账号等关联。探针主机导入不会自动配置 SSH，SSH 地址和凭据需另行设置。

「解除绑定」保留本机资产和远端资源；「移除连接」删除本机保存的连接凭据，也保留已导入资产和远端资源。移除后原资产无法继续读取该连接的状态。

### 修改 DNS

在域名资源或已绑定域名详情中点击「管理 DNS」。新增或编辑后先点击「预览变更」，核对修改前、修改后的记录，再点击「确认应用变更」。删除记录同样先预览再确认；确认会立即向 Cloudflare 提交，预览页会显示有效期。

当前支持新增、编辑 A、AAAA、CNAME、TXT、MX、NS。SRV、CAA、HTTPS 等高级类型可查看、删除，编辑请到 Cloudflare 控制台完成。

记录名称填写完整域名，例如 `www.example.com`；根域名填 `example.com`，不填 `@`。TTL 填 `1` 表示自动，手动范围为 60–86400 秒；开启代理时使用自动 TTL。MX 需填写优先级。更多限制见 [DNS 支持](CLOUDFLARE.md#dns-支持)。

如果确认后发生网络错误，先刷新记录核对远端结果，再决定是否重新操作；写入结果不明确时，知屿不会自动重试。

## 部署并连接独立探针

探针由常驻服务端、主机 Agent 和知屿桌面组成。Agent 通过 gRPC / HTTP/2 + protobuf 向服务端上报；桌面通过 HTTPS API 读取和管理。它使用知屿自己的协议，不兼容 Nezha Agent。

1. 按 [独立探针部署说明](../services/probe/README.md#部署服务端linux) 构建并部署服务端，准备服务域名、TLS 证书和独立的管理员 Token。仓库提供 systemd 单元和 Docker Compose，详见该文档。
2. 在知屿添加「知屿独立探针」连接，填写服务端地址，如 `https://probe.example.com:8008`，以及管理员 Token。地址填写服务根地址，不附加 `/api/v1`。
3. 点击「注册探针主机」，填写名称并生成凭据。界面只显示一次 `client-uuid` 与 `client-secret`，可用「复制 Agent 凭据」保存对应的 `id` 和 `secret`。
4. 在采集主机上复制 [Agent 配置示例](../services/probe/deploy/agent.example.json)，填入服务端 `endpoint`、该主机的 `id` 和 `secret`。管理员 Token 不填入 Agent 配置；每台主机使用自己的凭据。配置文件权限与服务安装步骤见 [桌面连接与 Agent 注册](../services/probe/README.md#桌面连接与-agent-注册)。
5. 启动 Agent 后，在资源卡片点击「指标与历史」查看数据。点击「导入或绑定资产」，将其关联到服务器资产。

Agent 默认每 3 秒采样，可配置为 1–4 秒；连接中断会自动重连。Agent 只采集并上报指标，没有远程终端、执行脚本或远程命令功能。

公网使用 TLS。仅在受信任本机或私网使用明文时，服务端、Agent 与桌面连接都需显式启用相应选项；具体条件见部署说明。Cloudflare Tunnel 能访问网页登录页，不代表同一路由能承载公网 gRPC，部署时要分别验证 Agent 上报与桌面 API。

「撤销主机」会使该主机凭据立即失效，并删除服务端对应主机与历史；需要重新接入时，应重新注册。请勿用它代替仅解除本机资产绑定。

### 添加 HTTP/TCP 检查

在探针连接中点击「新增服务检查」，选择协议并填写目标：HTTP/HTTPS 填完整 URL，TCP 填 `主机:端口`。默认每 60 秒检查一次、5 秒超时；间隔支持 10–3600 秒，超时支持 100–30000 毫秒且不得超过检查间隔。

检查由常驻服务端执行，目标必须能从服务端访问。HTTP 以 `2xx` 为正常，不跟随跳转，因此应填写最终地址；TCP 以建立连接成功为正常。检查不携带管理员 Token 或 Agent 凭据，也不提供网站登录配置。

点击「延迟与记录」可查看 1 小时、24 小时或 7 天的延迟曲线和检查记录；也可将检查绑定为服务资产，在资产详情查看。修改检查目标会清空该检查原有历史；删除检查会停止检查并删除其历史。

## 自动刷新、缓存与锁库

探针凭据不依赖资产密钥库解锁，锁库不会阻止探针监控。正在显示的探针工作区及已绑定探针的资产详情每 5 秒读取一次状态；Cloudflare 资源每 60 秒刷新。窗口隐藏或离开相应页面后，不继续为该视图轮询；重新显示时会读取状态。

这些间隔是桌面读取频率，不是后台采样频率。只要服务端和 Agent 仍运行，关闭知屿也会继续采集、保留历史并执行服务检查。

重复读取会复用短期缓存，并合并正在进行的相同请求；点击「刷新」可主动更新资源清单。页面显示上次同步时间和缓存标记；请求失败时会保留上次成功的数据并提示错误，旧数据不代表当前仍正常。

## 如何理解指标与历史

- 主机尚无样本时显示等待上报；15 秒没有有效上报则显示离线。离线仍保留最后已知指标，要结合最近上报时间判断。
- 未采集到或系统不支持的指标显示 `—`，不补成零。首次 CPU、网络速率需要后续样本才能计算；当前没有通用 GPU 采集器，GPU 保持缺省。
- 主机历史图展示 CPU、内存、磁盘百分比，可选 1 小时、24 小时、7 天；磁盘对应系统分区。当前指标还包括网络、Swap、运行时间、负载、连接数、进程数和可用温度。
- 主机网络累计值来自操作系统接口计数器，可能包含虚拟接口及回环流量，不等于服务商账单流量。
- 历史每 30 秒保留最新样本，保留 7 天；长时间范围会抽样展示。历史曲线不是每次上报的完整回放，缺失数据不补零。
- 服务检查延迟曲线只绘制成功检查；失败记录仍可查看。24 小时可用率按已有历史样本中成功的比例计算，无样本时为空。服务端停机期间缺失的检查不计为成功，也不补造失败；该比例不是按时间计算的 SLA。

服务端部署、安全边界、历史保留、备份和 API 细节见 [独立探针说明](../services/probe/README.md)。本指南说明当前代码提供的使用流程，不表示已在用户生产服务器部署，或已使用真实 Cloudflare Token 完成联调。

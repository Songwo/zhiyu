## 设计原则

1. **分层**：L1 内存（渲染进程 LRU）→ L2 本地缓存目录 `userData/cache/`（桌面版；网页版用 IndexedDB/OPFS）→ L3 数据源（IMAP/API/文件）。
2. **单写者**：每个缓存域只有一个写入方，避免并发撕裂；沿用现有 `this.writes` 串行化模式（`agent-service.mjs:136`）。
3. **失效双保险**：内容签名（版本）+ TTL，二者任一失效即回源；缓存损坏按未命中处理，静默重建，绝不报错给用户。
4. **敏感数据边界**：密码、令牌、密钥值**永不**进任何缓存层；邮件正文/附件属敏感内容，磁盘缓存必须用主密码库密钥加密，锁库即失效（与 `vault.enc` 同生命周期）。
5. **冷启动不劣化**：缓存目录被清空时行为与 0.8.0 完全一致。
6. **可观测**：设置页显示各缓存体积与命中率，支持分类清理。

## 分模块设计

### 1. RAG 索引签名复用（收益最大、风险最小，优先做）

- 签名 `sig = sha256(资产白名单字段序列化 + 知识文档 id/长度列表 + 分块参数版本)`。
- `prepare()`：签名与 `rag-index.json` 内保存的签名一致 → 直接反序列化复用（MiniSearch `loadJSON`），跳过构建与写盘；不一致 → 现行重建流程 + 写入新签名。
- 嵌入向量缓存（`rag-vectors.json`）已有 signature 机制（`agent-service.mjs:321`），对齐复用。
- 验收：同一会话第二个问题跳过重建（日志计数器），结果与重建完全一致（对比测试）。

### 2. 邮件读缓存（正文/列表/附件三层）

- **文件夹列表**：`cache/mail/<mailboxId>/folders.json`，版本 = IMAP `UIDVALIDITY`/`UIDNEXT`；打开邮箱先展示缓存、后台刷新后差异更新。
- **邮件列表**：每文件夹分页缓存（`list-<page>.json`，键 = 文件夹 + 分页游标 + UIDNEXT）；命中且 UIDNEXT 未变直接返回，标记 `stale: false`。
- **正文**：`cache/mail/<mailboxId>/body-<uid>.enc`，**vault 密钥加密**；命中免 IMAP 拉取。锁库清理解密能力但保留密文，解锁后可继续命中。
- **附件**：已下载附件存 `cache/attachments/<hash>.enc`（同样加密），重复查看/另存不再下载。
- 配额：邮件缓存合计默认 200MB，LRU 驱逐；设置页可调。

### 3. 远程图片缓存与授权延续

- 授权加载过的图片按 URL sha256 落盘 `cache/images/`（明文缓存位图可接受：图片本身经 sanitize 后才显示，不含凭据）。
- 「本封邮件允许加载图片」授权记录随正文缓存保存（邮件粒度，含 Message-ID），下次打开同一封邮件不再询问。
- 明确不做：全局自动加载所有远程图片（保持逐封授权的安全姿态）。

### 4. 对话历史分片

- 桌面版：`conversations/<id>.json` 分文件 + `conversations/index.json` 轻量索引（id/标题/时间/条数）。
- 问答界面首屏载入最近 50 条，上滑增量加载；导出/搜索仍合并全量。
- 迁移：首次启动把旧 `conversations.json` 拆分归档，原文件重命名 `.migrated` 保留一版。

### 5. 图片出库（base64 → 缓存目录引用）

- 头像与资产图片保存为 `cache/assets/<sha256>.png`；`profile.json`/`assets.json` 仅存引用字段 `imageRef`。
- 主进程 IPC `image:read(ref)` 返回 data URI（渲染层无感）；`image:write` 统一写缓存。
- 迁移：启动时惰性提取存量 base64（读到哪张提哪张），全部迁出前双写兼容。

### 6. 指标历史追加化

- `metrics.json` → `metrics/` 目录按天 JSONL 追加（一行一样本），内存聚合窗口读最近 N 天；保留 30 天自动清理。
- 采样频率不变的前提下，写放大从「全文件」降到「一行」。

### 7. 网页版持久化（可选，独立开关）

- 资产快照 localStorage → IndexedDB（配额从 ~5MB 提升到可用空间级别），键结构不变。
- PGlite 挂载 OPFS（`PGlite({ dataDir: "idb://nanpad" })` 语法按版本适配），实现真持久化；不可用时回退内存并提示。
- 该项不改桌面版任何行为。

### 8. 缓存管理界面

- 「设置 → 存储」：分类显示体积（邮件正文/附件/图片/头像资产/其他），命中统计（问答跳过重建次数、邮件缓存命中率），分类清理 + 一键清空。
- 锁库行为：加密缓存保留密文、清除内存密钥；「锁库清空缓存」作为可选强化项（默认关）。

## 非目标

- 不缓存任何密钥值、令牌、密码（含内存层）。
- 不做跨设备缓存同步。
- 不改变问答安全边界（缓存只影响速度，不影响模型可见内容）。

## 验证计划

- 单测：签名失效（改资产/改文档/改分块参数）→ 必须重建；签名一致 → 必须复用；缓存文件损坏 → 按未命中处理。
- 性能基准脚本 `scripts/bench-cache.mjs`：问答第二问耗时、文件夹二次打开耗时、重复查看附件耗时、内存峰值；输出前后对照表写入 `docs/releases/v0.9.0.md`。
- 加密缓存安全测试：锁库后磁盘密文不可解；解锁后命中不回源。
- 全量回归：`npm test` + 既有集成套件（agent / mail-client / extension）。
